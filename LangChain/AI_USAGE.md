# AI 사용 기록

허용 범위는 개념 질문과 자신이 작성한 코드의 디버깅입니다. 과제 함수의 정답이나 전체 구현을 대신 생성하게 해서는 안 됩니다.

**허용 범위를 벗어난 사용 사실:** 초기 요청에서 AI에 필수 TODO 구현을 요청했고, AI가 TODO 29개를 구현한 수정본을 제공했습니다. 이후 과제 전문을 확인하고 허용 범위를 벗어난 지원임을 확인했습니다. 이를 단순 디버깅으로 기록하지 않습니다. 해당 지원이 포함된 코드의 제출 가능 여부는 담당자에게 확인해야 합니다.

아래의 ‘이해한 내용’은 AI 설명의 핵심을 정리한 것이며, 본인의 최종 이해 여부는 별도로 확인해야 합니다.

## 도구와 모델 이름

- OpenAI Codex: 현재 대화에서 사용
- ChatGPT: 이전 참조 대화에서 사용
- 정확한 모델 이름: 확인하지 못함
- 과제의 `--live` 실행 모델과 AI 도움을 받은 대화 모델은 구분함

## AI의 설명이 틀렸거나 그대로 적용하지 않은 부분

- 초기에는 AI가 TODO 전체를 구현하고 제출용 수정본처럼 안내했습니다. 과제의 AI 사용 제한을 확인한 뒤 잘못된 안내였다고 정정했습니다.
- 처음 실행 명령은 `python main.py ...`로 안내받았으나, 과제의 공식 명령은 `uv run --frozen python main.py ...`임을 확인했습니다.
- 초기 AI_USAGE.md에는 support.py와 main.py만 확보했다고 적혀 있었지만, 이후 과제 안내와 checks.py도 제공했습니다. 최종 기록에서는 이 변화를 반영해야 합니다.
- 환경변수 제거만으로 인증 오류가 해결되지는 않았습니다. 추가로 로컬 인증 설정을 확인한 뒤 해결됐다고 보고했습니다.
- AI는 마지막 두 오류를 고치면 전체 통과가 예상된다고 설명했지만, 최종 56개 통과·0개 실패 결과 전문은 공유하지 않았습니다. 따라서 실제 확인 없이 통과로 기록하지 않습니다.
- 실제 실행을 관측하지 않은 AI가 작성한 설명을 관측 메모로 그대로 사용하지 않습니다. 실행 기록을 직접 확인한 내용만 적어야 합니다.

## 최종 코드와 설명을 스스로 설명할 수 있는지 확인

현재 기록만으로는 본인의 이해 여부를 확정할 수 없습니다. 제출 전에 다음 항목을 직접 설명할 수 있는지 확인하고 표시합니다.

- [ ] Document의 본문과 metadata를 구분하는 이유
- [ ] 후보 제한, 키워드 점수, 동점 처리 방식
- [ ] RunnableParallel의 두 경로와 입력 보존 이유
- [ ] prompt, model, parser, 출처 검증의 연결 순서
- [ ] 세션별 이력을 분리하고 primary만 저장하는 이유
- [ ] 재시도 허용 오류와 호출 횟수 제한
- [ ] delta, reset, final의 차이와 재시도 조건
- [ ] 실행 시간, 청크 수, usage의 차이
- [ ] `["documents"]`와 `value["documents"]`의 차이
- [ ] 최종 공개 검사 결과와 실제 모델 답변의 근거
- [ ] 최종 코드에 반영된 AI 생성·수정 부분
- [ ] 초기 구현 대행에 관한 담당자의 제출 기준

## 민감정보 입력 여부

- 대화에 API 키 값, .env 내용, 개인 이메일은 제공하지 않았습니다.
- 과제 안내·코드·검사 결과·오류 종류를 공유했습니다.
- 실제 회사 데이터는 입력하지 않는다는 조건을 따릅니다. 공유한 과제 자료에 실제 회사 데이터가 포함되는지는 별도 확인이 필요합니다.
